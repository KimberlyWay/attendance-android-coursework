# Учёт посещаемости учебной группы

Учебное Android-приложение для простой отметки присутствия студентов по дням. Интерфейс на русском языке. Проект написан на Java, данные сохраняются на устройстве в SQLite. Сервер, регистрация и интернет для работы приложения не нужны.

## Что умеет приложение

- Добавлять студентов по имени и фамилии и удалять их с подтверждением.
- Выбирать дату в календаре.
- Менять отметку нажатием на кнопку: «Не отмечен», «Присутствовал», «Отсутствовал», «Опоздал».
- Показывать суммарное число отметок каждого типа по каждому студенту.
- Сохранять данные между запусками на том же устройстве.

Одна отметка относится к студенту и дате, без разделения на отдельные пары и предметы. Удаление студента удаляет все его отметки. При удалении приложения данные тоже удаляются. Перенос данных на другое устройство и восстановление резервной копии не реализованы.

## Важное перед началом

Сборка GitHub Actions создаёт **debug APK** для установки и учебной демонстрации; это не подписанный ключом разработчика release APK. Файл появляется как артефакт запуска Actions, а не в разделе Releases. GitHub-репозиторий, Actions и сборка для этого проекта пока не проверены из текущего окружения. При проблеме откройте журнал действия и найдите первое сообщение об ошибке.

## 1. Создание репозитория и загрузка проекта

1. Распакуйте архив проекта на компьютере. Внутри должна быть папка `attendance`. Важно: после извлечения убедитесь, что внутри неё лежат `settings.gradle`, `build.gradle`, папка `app` и скрытая папка `.github`.
2. На GitHub создайте новый пустой репозиторий, например `attendance-app`. Не добавляйте при создании отдельные README, `.gitignore` или лицензию — README уже есть в проекте.
3. На компьютере откройте PowerShell в папке `attendance` (в Проводнике перейдите в папку, нажмите на адресную строку, введите `powershell` и нажмите Enter).
4. Если Git ещё не установлен, установите Git для Windows и перезапустите PowerShell. Выполните команды, заменив ссылку на адрес своего репозитория:

```powershell
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/attendance-app.git
git push -u origin main
```

При первом коммите Git может попросить указать имя и email. Тогда выполните `git config --global user.name "Ваше имя"` и `git config --global user.email "ваш-email"`, затем повторите `git commit`. При отправке изменений GitHub может предложить войти через браузер. Вместо пароля GitHub в HTTPS используется вход через Git Credential Manager или токен.

**Важно:** файл `.github/workflows/build-apk.yml` должен оказаться именно в корне репозитория. Если загрузить саму папку `attendance` как вложенную директорию, Actions не найдёт workflow. В корне GitHub-репозитория должны быть видны `app`, `build.gradle`, `settings.gradle` и `.github`.

## 2. Как собрать и скачать APK через GitHub Actions

1. После отправки кода откройте репозиторий на GitHub и перейдите во вкладку **Actions**.
2. Выберите workflow **Android APK**, затем последний запуск. Сборка стартует автоматически после `push`; её также можно запустить вручную через **Run workflow**.
3. Дождитесь зелёной галочки. Если запуск красный, нажмите на него, затем на `build` и раскройте шаг с ошибкой.
4. На странице завершённого запуска найдите **Artifacts** и скачайте **attendance-debug-apk**. Для скачивания артефактов может потребоваться вход в GitHub.
5. Распакуйте скачанный ZIP — внутри будет `app-debug.apk`. Передайте его на телефон и откройте. Если Android попросит разрешить установку из этого источника, разрешение нужно выдать тому приложению, через которое открываете APK.

Артефакт хранится до 30 дней; по истечении этого срока запустите сборку повторно. Чтобы APK появился в разделе Releases, нужен отдельный релиз и прикрепление файла; данный workflow этого не делает.

## 3. Как открыть проект в Android Studio

1. Установите Android Studio и при первом запуске согласитесь на установку Android SDK.
2. Распакуйте архив в отдельную папку, например `Документы/attendance`. Либо используйте локальный клон репозитория.
3. В Android Studio выберите **File → Open** и укажите именно папку, внутри которой находится `settings.gradle`, то есть корень проекта `attendance`.
4. Доверьте проекту выполнение кода, если уверены в его происхождении. Дождитесь синхронизации Gradle. При необходимости установите предложенные компоненты Android SDK Platform 35 и выберите JDK 17 в **Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK**.
5. Проект не содержит Gradle Wrapper. В настройках Gradle выберите установленный локально **Gradle 8.9**, либо создайте wrapper командой `gradle wrapper --gradle-version 8.9` из корня проекта, если Gradle уже установлен, и после этого выберите использование wrapper. Для автоматической сборки GitHub Actions wrapper не нужен.
6. Подключите телефон с включённой отладкой по USB либо запустите эмулятор, выберите устройство и нажмите **Run ▶**. Минимальная версия Android — 6.0 (API 23).
7. Для создания APK выберите **Build → Build Bundle(s) / APK(s) → Build APK(s)**. Файл окажется по пути `app/build/outputs/apk/debug/app-debug.apk`.

Название пунктов меню может немного отличаться в разных версиях Android Studio. Первая синхронизация скачивает зависимости и требует интернет.

## 4. Как убрать Git из копии для Android Studio

**Лучше всего:** скачайте репозиторий через **Code → Download ZIP** и распакуйте в новую папку. В таком архиве нет истории и папки `.git`, поэтому проект не будет привязан к Git. Откройте полученную папку в Android Studio. При этом `.github` может оставаться — это обычная папка с настройкой сборки, а не история Git.

Если проект уже склонирован и нужно убрать привязку только в его локальной копии:

1. Закройте проект в Android Studio и убедитесь, что нужные изменения сохранены или отправлены в GitHub.
2. Откройте PowerShell **именно в корне локального проекта**, где находится `settings.gradle`.
3. Проверьте содержимое `Get-ChildItem -Force` и убедитесь, что там есть папка `.git`.
4. Чтобы убрать привязку, выполните:

```powershell
Remove-Item -LiteralPath .git -Recurse -Force
```

Команда удаляет локальную историю, настройки удалённого репозитория и все локальные данные Git в этой копии. Репозиторий на GitHub она не удаляет. Несохранённые или неотправленные коммиты после удаления могут быть потеряны. Не выполняйте команду, если локальная история вам нужна. В некоторых рабочих деревьях `.git` может быть файлом; безопаснее тогда использовать отдельную копию из ZIP.

5. При желании удалите из этой **отдельной копии** папку `.github`: в ней лежит workflow сборки GitHub Actions. Исходный код и работа приложения от неё не зависят. Однако если удалить её из репозитория и отправить изменение в GitHub, автоматическая сборка перестанет запускаться.
6. Если Android Studio всё ещё показывает Git, откройте **Settings → Version Control**, выберите привязку проекта и удалите её кнопкой `−`, затем нажмите **Apply**. Также можно просто закрыть проект и открыть папку заново.

Служебные папки `.idea`, `.gradle` и `build` относятся к настройкам IDE, кэшу и результатам сборки. Их не требуется удалять ради отключения Git; часть из них Android Studio создаёт заново. Скрытие папок в панели Project зависит от режима отображения и не удаляет их с диска.

## 5. Типичные проблемы

- **Во вкладке Actions пусто:** проверьте расположение `.github/workflows/build-apk.yml` в корне репозитория и что файл закоммичен и отправлен.
- **Ошибка загрузки SDK или зависимостей:** откройте полный лог ошибочного шага; проверьте доступность GitHub, Google Maven и Maven Central. Не закрывайте причину без просмотра лога.
- **Android Studio не синхронизирует проект:** проверьте JDK 17, Gradle 8.9, установленную платформу SDK 35 и доступ к репозиториям. В проекте отсутствует wrapper до его создания.
- **Студент исчез вместе с отметками:** это предусмотрено при подтверждении удаления студента. Восстановление не реализовано.
- **APK не устанавливается:** проверьте версию Android, разрешение на установку и текст ошибки. Обновление приложения, подписанного другим ключом, может потребовать удаления старой версии, что удалит её локальные данные.
